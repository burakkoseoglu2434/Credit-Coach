# Requirements Archive: Credit Coach v1.0 Brownfield Baseline

**Archived:** 2026-03-14
**Status:** Historical reconstruction from imported planning and execution documents

## Delivered in v1.0

- [x] **MODEL-01**: System can train and evaluate a reproducible credit risk model with explicit backend selection and fallback behavior
- [x] **MODEL-02**: System records model metadata needed to explain training backend and runtime decisions
- [x] **MODEL-03**: System supports calibration and risk-threshold based approval decisioning
- [x] **RECOURSE-01**: System can generate recourse plans for denied customers across multiple horizons and strategies
- [x] **RECOURSE-02**: System scores candidate plans against approval, reliability, and worst-risk-margin gates
- [x] **RECOURSE-03**: System supports high-risk segment handling through dedicated policy or objective paths
- [x] **RECOURSE-04**: System can evaluate sequential or trajectory-style coaching progress over time
- [x] **RECOURSE-05**: System enforces feasibility constraints so plans remain operationally realistic
- [x] **XAI-01**: System can generate explainability outputs for decisions and recourse plans
- [x] **XAI-02**: System tracks explainability confidence or stability diagnostics where available
- [x] **EVAL-01**: System can run batch recourse evaluation on large customer sets and produce KPI summary artifacts
- [x] **EVAL-02**: System can benchmark recourse quality against challenger or baseline methods
- [x] **EVAL-03**: System can run stress, fairness, and backtesting evaluations tied to release decisions
- [x] **EVAL-04**: System can compare multiple experiment variants and aggregate seed-level results
- [x] **OPS-01**: System emits monitoring and telemetry artifacts suitable for production operations
- [x] **OPS-02**: System defines production runbooks and release gates that match generated artifacts
- [x] **OPS-03**: System supports audit-friendly logging and operational security controls

## Carried Forward to v1.1

- [ ] **KPI-01**: System maintains denied-to-approved lift at or above the current business target in repeated production-like runs
- [ ] **KPI-02**: System maintains denied high-risk lift without violating fairness or reliability thresholds
- [ ] **KPI-03**: System keeps latency and error rates within release-gate limits during smoke and batch workflows
- [ ] **KPI-04**: System reports gate pass/fail status with enough detail to explain a GO or NO_GO decision

## Deferred Beyond v1.1

- [ ] **PROD-01**: Multi-user application surfaces for internal operators and external credit applicants
- [ ] **PROD-02**: Workflow automation for recurring experiment reviews and release readiness checks
- [ ] **PROD-03**: Expanded governance dashboards for ongoing monitoring beyond artifact-based reports

## Notes

- This archive preserves the broad capabilities established before the new GSD milestone structure was reconstructed.
- KPI reliability and fairness stability were intentionally carried forward because imported reports show they remain the main release blockers.
