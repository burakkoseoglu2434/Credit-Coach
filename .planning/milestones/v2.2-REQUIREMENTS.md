# Requirements: Credit Coach v2.2 Winner Integrity & Consumer Consistency

**Status:** ✅ SHIPPED 2026-04-02
**Defined:** 2026-03-24
**Archived:** 2026-04-02
**Core Value:** Fix selected-winner integrity and consumer-surface consistency before any threshold widening or approval-rate optimization.

## v2.2 Requirements

### Winner Integrity

- [x] **WINT-01**: Collection reruns never select a plan whose `recommendation_validity_status` is `invalid`
- [x] **WINT-02**: If validity filtering empties a preferred candidate subset, planner fallback widens only to other valid candidates or returns no valid winner
- [x] **WINT-03**: Selected customer truth records the winning plan's validity and provenance consistently across raw and flat artifacts

### Dice Lane Enforcement

- [x] **DICE-01**: `dice` candidates carry the same action-level and plan-level validity fields into planner selection as internal candidates
- [x] **DICE-02**: Invalid `dice` candidates remain visible in diagnostics but can never be emitted as selected winners

### Selected Surface Consistency

- [x] **CONS-01**: `best_plan_id`, selected plan rows, external decision summaries, and collection metrics remain mutually consistent for each customer
- [x] **CONS-02**: No external `CONDITIONAL` output points at a selected plan row whose plan status is `REJECTED`
- [x] **CONS-03**: Operator packets and explanation packs render recommendation text from the selected valid plan only, with no leakage from discarded invalid winners

### Operator Packet Coherence

- [x] **OPER-01**: Operator short view never renders an invalid selected recommendation as a recommended next action
- [x] **OPER-02**: Approved packets with no active drivers render no fallback blockers
- [x] **OPER-03**: Warning badges and appendix diagnostics remain available without creating contradictory short-view guidance

## Requirement Outcome Notes

- All 11 milestone requirements shipped and passed both phase verification and the milestone audit.
- Three large-sample reruns proved winner integrity, DICE selected cleanliness, selected-surface consistency, and operator packet coherence on the tracked acceptance metrics.
- `no_valid_winner` empty-state behavior remains automated-test-proven rather than cohort-proven because the audited reruns contained zero naturally occurring empty-state customers.

## Future Requirements Carried Forward

### Threshold and Outcome Optimization

- **THR-01**: Decision thresholds can be widened safely using validity-clean winner evidence
- **APRV-01**: Approval and conditional rates can be optimized without degrading selected-surface trust

### Offer and Readiness Expansion

- **OFFR-01**: Offer-maturity lanes can improve business outcomes instead of remaining descriptive only
- **READ-01**: Readiness semantics can be widened into a larger movable queue once selected truth is stable

## Out of Scope

| Feature | Reason |
|---------|--------|
| Threshold widening or approval-rate optimization inside v2.2 | Trust repair had to finish before aggressiveness tuning |
| Redesign of Phases `40`, `40.5`, `41`, `42`, `42.5`, or `43` | These were fixed baselines for the milestone |
| New borrower-facing channels or mobile surfaces | v2.2 focused on winner and consumer-truth integrity, not channel expansion |
| Live institution integrations or compliance automation | Not required to close selected-winner trust gaps |
