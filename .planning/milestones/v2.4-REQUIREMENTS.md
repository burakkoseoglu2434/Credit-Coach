# Requirements: Credit Coach v2.4 Recourse Capability Expansion & Action Semantics

**Status:** ✅ SHIPPED 2026-04-05
**Defined:** 2026-04-03
**Archived:** 2026-04-05
**Core Value:** Generate customer-specific credit action plans that are actionable, behaviorally realistic, governance-safe, and measurably useful enough to improve denied-customer outcomes without breaking enterprise trust.

## v2.4 Requirements

### Action Semantics Taxonomy

- [x] **SEM-01**: Define canonical action categories: utilization, burden reduction, delinquency cleanup, verification, restructuring, application flexing, institution relief
- [x] **SEM-02**: Add action_owner field (customer, institution, hybrid)
- [x] **SEM-03**: Verify all existing actions map into the taxonomy with zero unclassified leftovers

### Feature Mapping

- [x] **MAP-01**: Map the 48 features into actionable transformations
- [x] **MAP-02**: Add action_type, numeric_target_required, and institution_required fields
- [x] **MAP-03**: Achieve ≥ 80% coverage mapped to at least one action

### DICE Space Expansion

- [x] **DICE-01**: Expand DICE to support loan_amnt, installment, term
- [x] **DICE-02**: Expand DICE to support selected delinquency and verification_status features
- [x] **DICE-03**: Ensure Phase 46 gates hold (annotation completeness, semantic quality, contender eligibility)
- [x] **DICE-04**: Maintain valid diversity and winner integrity without regression

### Heuristic / Institution Action Lane

- [x] **INST-01**: Add limit increase, structure modifications, settlement, and debt consolidation heuristics
- [x] **INST-02**: Add institution-triggered relief lane
- [x] **INST-03**: Add institution_condition, offer_required_flag, offer_feasibility fields
- [x] **INST-04**: Verify heuristic actions surface in candidate pool behind proper gates

### Multi-Path Recourse Generation

- [x] **PATH-01**: Generate Path A (customer-only), Path B (institution-assisted), and Path C (hybrid) per customer
- [x] **PATH-02**: Ensure independent rankability and internal coherence for each path
- [x] **PATH-03**: Achieve multi_path_rate ≥ target threshold with structurally different paths

### Action Semantics Rendering

- [x] **REND-01**: Add a metric-aware phrasing template system (e.g., "Utilization 27% → 19%")
- [x] **REND-02**: Ensure no broken or generic recommendation text is generated
- [x] **REND-03**: Verify selected plans all produce a coherent narrative summary

### Validation & Cohort Evaluation

- [x] **EVAL-01**: Implement multi_path_rate, action_diversity_index, non_utilization_action_rate, institution_action_rate, selected_plan_category_distribution metrics
- [x] **EVAL-02**: Measure structural_cohort_limited reduction effect
- [x] **EVAL-03**: Ensure no regression in selected_invalid_winner_count, dice_contender_rules, selected-surface consistency, or operator packet coherence

## Requirement Outcome Notes

- All 23 milestone requirements shipped, passed phase verification, and passed the v2.4 milestone audit.
- The milestone proved capability expansion: richer action semantics, deterministic mapping, safe DICE expansion, institution/hybrid generation, deterministic multi-path grouping, deterministic rendering, and cohort-level evidence packaging.
- The milestone did **not** prove business lift. No archived evidence shows that the richer v2.4 surface already creates safe approval or conditional uplift in real denied cohorts.
- Honest one-path and `no_valid_winner` cases remain part of the shipped contract; v2.4 does not fabricate synthetic path diversity to satisfy a planning narrative.

## Future Requirements Carried Forward

### Movement Outcome Proof

- **MOVE-01**: Determine whether the shipped v2.4 surface softens `structural_cohort_limited` for denied, high-risk denied, and `pilot_mixed` cohorts
- **MOVE-02**: Determine whether non-utilization and institution/hybrid paths create execution-aware movement rather than recommendation variety alone
- **MOVE-03**: If lift remains absent, isolate whether execution realism, data richness, or offer availability is the dominant next bottleneck

## Out of Scope

| Feature | Reason |
|---------|--------|
| Trust-logic redesign during v2.4 | The milestone consumed the shipped v2.2 trust baseline as fixed |
| Planner redesign during v2.4 | Pathing, rendering, and evaluation stayed additive rather than changing winner semantics |
| New action types beyond the v2.4 plan | The milestone focused on the defined expansion surface only |
| Direct approval-lift claims from v2.4 alone | Business movement required explicit evidence, not inference from diversity |
| Live institution integrations or compliance automation | Not required for v2.4 capability expansion |
