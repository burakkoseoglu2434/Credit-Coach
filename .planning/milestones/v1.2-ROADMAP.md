# Milestone v1.2: Recommendation Quality Hardening

**Status:** ✅ SHIPPED 2026-03-16
**Phases:** 12-16
**Total Plans:** 15

## Overview

This archive captures the milestone that turned Credit Coach from a gate-aware recourse engine into a behavior-aware, trajectory-aware, offer-aware, and learning-capable recommendation system. The work expanded action realism, modeled execution behavior, promoted multi-phase trajectories to first-class planning objects, added institution-side offer optimization, and closed the loop with delayed outcome learning signals.

## Phases

### Phase 12: Action Realism & Feasibility Expansion

**Goal**: Expand the action space from feature edits to real-world financial and institutional actions, and strengthen feasibility constraints.  
**Depends on**: Phase 11 / v1.1 baseline  
**Plans**: 3 plans

Plans:
- [x] 12-01: Redesign the action taxonomy for behavioral, structural, and institutional plan actions
- [x] 12-02: Expand feasibility realism with monthly, income, utilization, and financial-capacity constraints
- [x] 12-03: Add action dependency and conflict modeling for incompatible recommendation combinations

### Phase 13: Behavior-Aware Recourse

**Goal**: Introduce execution probability modeling so recommendations consider the likelihood that a user will actually perform the suggested actions.  
**Depends on**: Phase 12  
**Plans**: 3 plans

Plans:
- [x] 13-01: Add an action-execution probability model and planner integration
- [x] 13-02: Update planner scoring to use expected utility under gate constraints
- [x] 13-03: Simulate partial execution, failed steps, and mixed-execution scenarios

### Phase 14: Sequential Recourse Planning

**Goal**: Transition from single-plan recommendations to multi-phase improvement trajectories.  
**Depends on**: Phase 13  
**Plans**: 3 plans

Plans:
- [x] 14-01: Build a multi-phase planning model for near-, mid-, and longer-horizon actions
- [x] 14-02: Add dynamic trajectory simulation with timing, inertia, and partial execution
- [x] 14-03: Balance short-term feasibility against long-term risk improvement in the optimization objective

### Phase 15: Policy Optimization Layer

**Goal**: Integrate institutional offer optimization with recourse planning.  
**Depends on**: Phase 14  
**Plans**: 3 plans

Plans:
- [x] 15-01: Add institution-side offer actions into the recourse action space
- [x] 15-02: Score offers against expected recovery, risk, fairness, and reliability constraints
- [x] 15-03: Model user acceptance probability for offers and fold it into expected recovery

### Phase 16: Outcome Feedback & Learning Loop

**Goal**: Enable the system to learn from real-world outcomes.  
**Depends on**: Phase 15

Plans:
- [x] 16-01: Expand decision logging to capture recommendation, offer, and execution context

## Milestone Summary

**Key Decisions:**
- Typed actions remain hybrid: `action_key` is user-facing while `feature_name` stays the effect anchor.
- Behavior-aware, trajectory, offer, and learning-loop evidence remain mandatory supporting evidence and do not override inherited governance gates.
- `phases[]` became the canonical trajectory semantic layer while the weekly coaching loop remained the simulation seam.
- Offer acceptance stays distinct from plan execution probability, and off-policy evaluation remains proxy-vector-first and control-baselined.

**Issues Resolved:**
- Raw feature-edit outputs were replaced by typed behavioral, structural, and institutional recommendations.
- Recommendation ranking now accounts for execution likelihood, partial execution, and short-term-first trajectory health.
- Institution-side offers can be optimized without bypassing fairness, reliability, telemetry, or action-realism safeguards.
- The repo now logs learning-grade decisions, ingests delayed outcomes, and publishes IPS or Doubly Robust evidence in review artifacts.

**Issues Deferred:**
- Operator-facing dashboards and richer product surfaces remain future productization work.
- Regulatory explanation layers remain separate from the technical recourse and governance contracts.
- Full online autonomous learning or policy auto-promotion remains intentionally out of scope.

**Technical Debt Incurred:**
- Large CLI orchestration modules still sit on the hot path for batch, suite, and challenger workflows.
- Local `gsd-tools.cjs` helper automation remains partially broken, so some planning workflows still require manual execution.
