  <name>Task 1: Implement a coverage diagnostics library (derived buckets; additive outputs only)</name>
  <files>credit-coach/src/credit_coach/evaluation/coverage_diagnostics.py</files>
  <action>
Create `credit_coach.evaluation.coverage_diagnostics` with a small, deterministic API:

- Input contract: accept either a `pandas.DataFrame` (preferred, when called from evaluation) or a path to `customer_level_analysis.csv`.
- Output folder contract: write to `output_dir/coverage_diagnostics/` (or `run_dir/coverage_diagnostics/` for post-hoc mode).
- Required outputs (lock filenames exactly):
  - `coverage_diagnostic_customer_breakdown.csv`
  - `coverage_diagnostic_summary.json`
  - `coverage_reason_frequency.csv`
  - `empty_state_decomposition.json`

Derived bucket taxonomy (diagnostic-only; do not change shipped codes):
- Produce a single primary `coverage_loss_bucket` per customer plus optional `coverage_loss_subreasons_json`.
- Buckets must be computable from `customer_level_analysis.csv` fields first (fast path). Only add optional second-pass buckets if additional artifacts are available.
- Minimum bucket set to cover the Phase 71 context:
  - `no_valid_path`
  - `valid_but_not_rankable`
  - `rankable_but_no_movement`
  - `movement_but_no_threshold_signal`
  - `latent_value_but_gate_suppressed`
  - `post_gate_surface_collapsed_to_empty_state`
  - `selected_plan_present` (non-empty baseline bucket for actionable customers)
  - `trust_blocked` (if any of the trust flags are non-zero)

Explicit thresholds (deterministic; written into metadata):
- define a single explicit epsilon for “non-trivial threshold signal”, default `gap_closure_epsilon = 0.05`
- define “movement-positive” using existing categorical proxies first:
  - movement-positive if `movement_potential in {weak,strong}` OR `path_reaches_threshold_flag == 1`

Segment reporting:
- Use `recoverability_bucket` as the raw segment field (`near_threshold`, `mid_risk`, `structural_limited`).
- Also emit a normalized segment label for reporting that maps:
  - `structural_limited` -> `hard_denied`
  - keep the others unchanged
- In all summaries, compute:
  - empty-state rate
  - actionability rate (e.g., `recommendation_mode == actionable`)
  - selected-plan availability (`selected_recommendation_source == selected_plan`)
  - derived bucket distribution

Implementation guardrails:
- Never mutate the input DF in-place (copy before adding columns).
- Ensure deterministic ordering and stable JSON formatting (sorted keys; explicit rounding where needed).
- Keep this module free of heavy JSONL parsing; mismatch analysis remains optional and can be added later.

Output column requirements (COV-01 clarity):
- In `coverage_diagnostic_customer_breakdown.csv`, include the mode outcome fields explicitly:
  - `recourse_mode`, `recommendation_mode`, `selected_recommendation_source`, `empty_state_flag`, `zero_action_flag`
  - plus the derived `coverage_loss_bucket`

Explicitly deferred in Phase 71 Wave 1 (ok to add later, but not required for COV-01..03):
- `coverage_diagnostic_report.md`
- `latent_vs_surfaced_mismatch.csv`
  </action>
